# 评测体系

> 企业智能知识库 Agent 平台文档集之一：检索消融与 Agent 评测的题目来源、指标口径、裁判参照系与复现记录。
> README 与本文表格中的指标数字均由脚本落盘为 JSON 后渲染；本文负责的是口径与复现记录，不是数字本身。

检索与 Agent 分两层评测：**检索层看召回，Agent 层看行为**。

<a id="sec-1"></a>
## 一、评测体系

### 1.1 检索消融（`eval/evaluate_retrieval_ablation.py`）

- `eval/qa_pairs.json`：**104 题**（可答 99 / 无答案 5），含 `gold_keywords`（标准答案文档关键词）、
  `expected_year`（期望年份）、`type`（题型：数字精确 / 政府信息公开 / 五年规划区分 / 年份区分 /
  主题语义 / 相似文本 / 无答案）。题目由 `generate_qa_pairs.py` 从真实语料生成，
  带三道校验闸门（必须溯源到原段落、必须含数字、与已有题去重），金标准可审计。
- 对比 4 种配置：`bm25` / `vector` / `hybrid`(+RRF) / `hybrid_year`(+年份策略，生产默认)。
  **四者跑的是 `rag.py` 的同一条代码路径，只是 `mode` 不同**——保证实验结论与线上行为一致。
- 指标：Recall@5、Recall@8、MRR@8、年份 Top-1 命中率、平均延迟、分题型 Recall@8。
- 无答案题不计入 Recall：检索层没有「拒答」语义，误召回率需要相似度阈值才能定义。

### 1.2 Agent 评测（`eval/evaluate_agent.py`）

- `eval/agent_tasks.json`：**39 题**，7 类：文档问答 15 / 统计问答 7 / 拒答 6 / 结构自省 3 /
  多工具协作 3 / 工具链 3 / 运行时状态 2（依赖 MCP）。
- 指标：任务完成率、工具选择正确率（`expected_all_tools` 支持要求调齐全部工具）、
  引用命中率、拒答正确率、LLM 裁判的正确性与忠实性（无幻觉）、平均延迟与迭代轮数。
- 裁判的参照系决定了这些数字是否成立，取舍过程与复现记录见 [1.4 节](#sec-1-4)。

### 1.3 结果口径

- 两个脚本各自落盘 JSON（`retrieval_ablation_result.json` / `agent_eval_result.json`），
  `render_results.py` 读 JSON 渲染成 README 表格。**文档与 README 中的数字均由脚本生成**——
  数据集一变旧数字即失效，重新运行即可；跑不出数据则显示「暂无数据」。
- 跑评测前**必须先停掉后端**：Milvus Lite 是单进程独占 `./milvus.db` 的。

<a id="sec-1-4"></a>
### 1.4 裁判的参照系（决定数字是否成立）

LLM 裁判看到什么，直接决定正确性与忠实性两项指标的真假。口径上有三个做法被逐一否掉：

- **不能提供整篇文档**：裁判会看到 Agent 根本没有检索到的内容，从而把无据的回答判成
  「有据可依」，**漏判**真实幻觉。
- **不能只提供检索结果的前若干字符**：早期实现取整篇后截 2000 字，会把「确实检索到、仅超出窗口」
  的内容误判为编造——上下两个方向的错都会犯。
- **不能不复现 executor 的截断**：生产链路里 `_serialize` + 按预算截断会把工具结果压到预算内。
  重放时若直接塞原文（不截），裁判看到的是 Agent 从未看到的资料，会**反过来冤枉它「漏答」**
  （实测：十二五「减少 8%」那句位于文档第 5068 字处，Agent 当时看不到）。

**最终做法**：`_replay_context()` 直接调用 `get_tool_map()` 中的**生产工具函数**重放同一批调用，
再用 executor 的 `_serialize` / `_truncate` 复现同样的截断，并按 **Agent 当时收到的同一套引文编号**
渲染，因此裁判看到的 `[n]` 与 Agent 写下的 `[n]` 指向同一份资料。
去重按**正文内容**而非 `id`——`rag.search` 返回的 `id` 是「本次检索内的展示序号 1..n」
（见 [《架构与模块设计》3.7 节](./architecture.md#sec-3-7)），跨调用必然重复，按 `id` 去重会让重放范围比 Agent 实际看到的更窄。

拒答判定同样分两层：关键词命中即判定，未命中再交裁判兜底——模型表示拒绝的措辞每轮不同，
仅依赖关键词表会漏判（早期的关键词表就漏了「没法」「帮不上忙」这类说法，把如实拒答记成失败）。

**复现记录**：统一口径后连跑 8 次，正确率 14/15、忠实性 15/15、完成率 39/39、
工具选择 33/33 次次一致；引用命中 7 次 18/18、1 次 17/18；拒答补上裁判兜底后 2 次均为 6/6。
修正前曾出现 11/15、13/15 两种数字，属于重放口径不一致产生的伪影，并非模型输出波动。
上下文预算三处缺陷修复后（见 [《架构与模块设计》4.3 节](./architecture.md#sec-4-3)），唯一稳定失败的那题也通过，正确率 14/15 → 15/15。

**教训**：裁判口径与生产口径必须同源。本 bug 的三层缺陷中有两层都是「裁判看到的 ≠ Agent 看到的」。
